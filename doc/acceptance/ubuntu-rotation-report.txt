Ubuntu rotation and desktop functional acceptance — 2026-11-02

Environment
Ubuntu 26.04 ARM64 in Parallels Desktop; Flutter 3.47.9; libmpv 0.41.0;
GTK 3.24.52 and GTK 4.22.4. Full Flutter application tested on Wayland/GTK 3.

Confirmed defect and fix
An independent native regression reproduced SIGABRT at 90 degrees in
mpv_render_context_render -> mp_image_crop (crop exceeds image dimensions).
Even output dimensions alone did not fix this defect.
Rotation now transforms decoded pixels using filters, with renderer-level
rotation disabled. Original container rotation is read from the selected
track and combined with the requested rotation. Mirrors remain composable.
API and worker state changes are serialized; output dimensions are synchronized.
Odd output sizes are preserved rather than silently rounded.
The example's reset-to-zero button now calls the common rotation API on Linux.

GTK compatibility limits
The standard Flutter Linux embedder is GTK 3. GTK 4 plugin source and standalone
window operations are tested, but a complete GTK 4 Flutter embedder is not
available here and has not been validated. Do not mix both GTK majors in one
process. AUTO follows the host GTK_VERSION; a matching custom GTK 4 host may
use KINETIC_PLAYER_GTK_VERSION=4.
GTK 4 window tests pass with GSK_RENDERER=cairo in this VM; the default GPU
backend did not complete fullscreen successfully. This is not claimed fixed.
The extra X11 window test did not complete; full runtime results above are for
Wayland. No Windows runtime re-test was performed in this session.
Desktop-unimplemented features (PiP, GIF recording, ads, danmaku and GSY GL
filters) remain outside desktop acceptance; they are not newly implemented.
